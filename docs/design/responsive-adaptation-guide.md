# Facedat 响应式与移动端适配规范

## 1. 文档状态

项目已完成第一轮响应式改造：

- demo 使用弹性最大宽度和移动间距；
- 一级、二级 Tab 在窄屏局部横向滚动；
- 参数行在手机下改为“名称/数值 + 跨行 Slider”；
- 贴花与妆容在手机下改为信息卡布局；
- 数据清洗弹窗使用视口安全宽度，按钮在手机下单列；
- viewport 已允许用户缩放。

本项目只做响应式组件，不在包内判断小程序/App，也不维护终端专用路由。

## 2. 原则

- 组件根据可用宽度适配，不根据 User-Agent 或 `window.innerWidth` 切换业务模板；
- 优先 Flex/Grid 自适应，只在布局需要结构变化时使用断点；
- 页面级不得横向溢出，Tab 等明确区域可以局部横向滚动；
- 移动端仍保留解析、查看、编辑（如 `lock=false`）和导出能力；
- 响应式样式不改变 props、事件、解析或导出结果；
- 所有窄屏验收同时使用长语言，避免只对中文调尺寸。

## 3. 断点策略

当前构建自动注入 common 的 `@phone`，但组件包长期不应依赖宿主不透明的断点值。建议在本包样式中明确记录并集中维护：

| 范围 | 建议宽度 | 主要策略 |
| --- | --- | --- |
| 手机 | `≤ 720px` | 单列、Tab 横向滚动、触控优先 |
| 平板/窄容器 | `721px–1023px` | 工具栏换行、妆容信息分组 |
| 桌面 | `≥ 1024px` | 保持当前信息密度 |

由于组件可能嵌在侧栏、弹窗或窄内容区，后续优先评估 container queries。若要兼容当前浏览器基线，可先用 viewport media query，但必须用 `min-width: 0` 和弹性布局保证窄容器不会立刻破版。

不要为每个设备型号新增断点。

## 4. 演示页容器

`App.vue` 只是 demo，但必须能代表组件真实可用范围。目标容器：

- 宽度 `min(100% - 32px, 980px)`；
- 桌面上下间距约 `48px`；
- 手机上下间距约 `20px`；
- `box-sizing: border-box`；
- 不使用内联样式。

`public/index.html` 已保留标准响应式 viewport，并允许用户缩放，以满足可访问性和大字号使用需求；后续不得重新加入 `maximum-scale=1.0` 或 `user-scalable=no`。

## 5. Upload

### 桌面

- 上传按钮保持明确主要操作，帮助链接位于其下方；
- 成功结果中的重置按钮和文件名不互相遮挡；
- 长文件名允许换行或中间省略，并保留完整 title。

### 手机

- 上传按钮宽度使用 `min(100%, 320px)`，不固定超出容器；
- 点击目标高度不小于 `44px`；
- 帮助链接允许换行，图标与首行对齐；
- Alert 描述可自然换行；
- 文件 input 仍可通过关联 label/button 触发，不依赖不可访问的 DOM id 全局查找。

## 6. 一级与二级 Tab

Face/Body 一级 Tab 数量多，手机上不应压缩成多行高度不一致的药丸：

- 外层使用局部横向滚动；
- 每个 Tab `flex: 0 0 auto`，保留至少 `44px` 触控高度；
- 隐藏滚动条时仍提供边缘渐隐或其他可滚动线索；
- 当前项切换后应自动保持可见（能用原生行为解决时不额外引入 JS）；
- Slot 中的数据清洗操作不能与 Tab 重叠，应在窄屏独占一行或进入操作区。

写实脸型的二级 `el-tabs` 同样局部滚动。不要给 `.el-tabs__nav` 强制 `width: 100%` 后再固定每项宽度，长语言应使用内容宽度与合理内边距。

## 7. 参数列表

当前每行结构是“名称 + 数值 + Slider”。目标布局：

### 桌面

```text
名称（稳定列宽） | 数值 | Slider（占剩余宽度）
```

### 手机

优先使用两行 Grid：

```text
名称                    数值
Slider（跨满整行）
```

规则：

- 名称、数值和轨道均设置 `min-width: 0`；
- 字段名允许换行，不能用固定中文宽度硬截断；
- 数值使用等宽数字或稳定对齐，避免滑动时布局跳动；
- 可编辑的 `el-slider` 与只读 `Slider` 占用相同布局空间；
- 只读 Slider 不应伪装成可拖动控件；
- `ResizeObserver` 在组件卸载时必须断开。

## 8. 妆容、贴花和价格行

桌面端可保持横向信息行，但应由 Grid 定义列，不依赖多个 `span` 的百分比和固定宽度混排。

手机端每个贴花项改为信息卡：

1. 图标 + 名称；
2. 颜色/翻转/免费状态；
3. 参数网格；
4. 价格。

要求：

- 图标固定尺寸，文本容器可收缩；
- 参数名称和数值成对显示，不依赖 DOM 序号选择器；
- 价格和总计不被挤出屏幕；
- 不存在价格时不保留空白固定列；
- 远程图片失败时布局仍稳定；
- 写实与写意使用相同响应式原则，不必强行使用完全相同 DOM。

## 9. 操作区与弹窗

- 导出按钮在桌面可并排，手机下根据数量变为单列或等宽双列；
- 按钮文案允许换行但不裁切图标；
- 数据清洗触发器使用真实 `button`/`el-button`，不能只用带 click 的 `div`；
- Dialog 宽度使用 `min(90vw, 合理最大宽度)`，不使用 `30%/90%` 两档；
- Dialog 底部按钮在 `320px` 宽度可完整显示；
- 文件下载前后的通知不会遮挡关键操作。

## 10. 触控与可访问性

- 主要触控目标至少 `44 × 44px`；
- 触屏不依赖 hover 才出现操作；
- 键盘可以到达上传、Tab、Slider、清洗、弹窗与导出；
- focus-visible 清晰且不被 overflow 裁切；
- 图标图片提供合适 alt，装饰图使用空 alt；
- 颜色不是状态的唯一表达；
- 支持页面缩放和系统大字号；
- 非必要动效遵循 `prefers-reduced-motion`。

## 11. 宿主边界

PVX 和 Mobile 当前存在直接引用本包组件、解析器和数据 JSON 的代码，也存在各自维护的移动端展示组件。本包的响应式改造只保证本包导出的 UI 组件可用：

- 不主动修改相邻仓库的专用页面；
- 不重命名被宿主直接导入的数据文件与字段；
- 若要让宿主删除重复移动组件，需要单独制定迁移计划并逐个页面验收；
- 宿主页面负责自己的头部、底部导航和 safe-area，本组件只保证内容区不溢出。

## 12. 验收矩阵

| 场景 | 视口/容器 | 检查重点 |
| --- | --- | --- |
| 最窄手机 | `320 × 568` | 无横向溢出、按钮完整、参数两行布局 |
| 常见手机 | `390 × 844` | Tab 滚动、妆容卡、Dialog、长语言 |
| 大手机 | `430 × 932` | 信息密度、触控间距 |
| 竖屏平板 | `768 × 1024` | 工具栏换行、参数列宽 |
| 横屏平板/窄桌面 | `1024 × 768` | 桌面布局切换临界点 |
| 桌面 | `1440 × 900` | 保持现有信息密度和最大宽度 |
| 窄嵌入容器 | `480px` 宽容器置于桌面 | 检查组件宽度而非仅视口宽度 |

每个尺寸至少覆盖：上传前、解析成功、写意脸型、写实脸型、体型、弹窗、长文件名、远程图片失败和英文长文本。
